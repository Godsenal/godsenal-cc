# CLAUDE.md

A Claude Code plugin marketplace (`godsenal`) with three plugins — `gbase` (dev workflow: review, polish, PR, monitor), `gapp` (app-building harness: idea → App Store), and `gshorts` (Korean content: faceless short-form videos, Instagram card news). No build step, no dependencies; everything is markdown skills. What each skill does lives in its own `SKILL.md` and in `README.md` — don't duplicate it here.

## Layout

```
.claude-plugin/marketplace.json     registry — one entry per plugin, with version
plugins/base/  → gbase              .claude-plugin/plugin.json, skills/<name>/SKILL.md (+ references/, scripts/), commands/*.md (legacy), evals/ (claude plugin eval cases),
                                    references/ (rules several skills share), .claude-plugin/factory.json (orchestrator slots),
                                    agents/*.md (subagent types, registered as gbase:<name>), hooks/ (SessionStart routing rule)
plugins/app/   → gapp               .claude-plugin/plugin.json, skills/<name>/SKILL.md (+ references/)
plugins/shorts/ → gshorts           .claude-plugin/plugin.json, skills/<name>/SKILL.md (+ references/)
scripts/check.py                    repo checks CI runs (.github/workflows/check.yml); tests for its contract check in scripts/test_check.py
scripts/gbase-run                   headless runner for factory.json slots (claude -p → result.json); tests in scripts/test_gbase_run.py
scripts/baseline.py                 one baseline.json per version (eval pass rates, read-budget, trend of ~/.gbase/runs) and `diff` of two; results under $GBASE_HOME/baselines/, never committed; tests in scripts/test_baseline.py
scripts/bench/run                   fixed work tasks (fixtures/<task>/: low, medium, high, headless, ui; the hard ones rootcause, blast, mirror, strict run only with --task, graded by a hidden test proven to fail the trap fix) on scratch repos with a fake gh, headless, nothing pushed; bench.json → baseline.py --bench; tests in scripts/test_bench.py
scripts/read-budget.py              characters a PR run loads into its main session, per route, and the session-start fixed part (hook text plus every listed gbase name and description); limits in scripts/read-budget.json (check.py enforces); tests in scripts/test_read_budget.py
scripts/triggers.py                 deterministic trigger check: TF-IDF over the skill listing, prompts in plugins/base/evals/triggers.json (train to tune a description on, held-out test that check.py judges); check.py prints its `triggers: rank1 N/M (P%)` line; tests in scripts/test_triggers.py
scripts/test_ship_prep.py, test_pr_status.py, test_added_comments.py, test_stage_delta.py   tests for the scripts the skills run: skills/branch-pr/scripts/ship-prep, skills/monitor/scripts/pr-status, skills/polish/scripts/added-comments, skills/go/scripts/stage-delta
scripts/pstack-sync.py              follows pstack (cursor/plugins): --check / --apply / --verify; lock, upstream snapshots, pending diffs in scripts/pstack/; tests in scripts/test_pstack_sync.py
scripts/refs-watch.py               watches other skill repos: --check / --update against scripts/refs/lock.json (head sha, SKILL.md blob shas); tests in scripts/test_refs_watch.py
```

Plugin names carry a `g` prefix (`gbase`); directories don't (`plugins/base/`).

## Conventions

- **New work goes in `skills/<name>/SKILL.md`.** `commands/` holds only the legacy `find-skills` command.
- **Every change bumps the version** in both `plugins/<p>/.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json` (patch for fixes/wording, minor for new or reworked skills) — installed plugins don't update otherwise. Update `README.md` when a skill's behavior or usage changes; update `plugin.json` keywords when skills are added or removed.
- **Read budget.** `work`, `go`, `branch-pr`, and `monitor` bodies hold only the steps every run takes and "when X, read Y". A branch only some runs take (a route's steps, a risk tier, a flag, headless, conflicts, replies) goes in that skill's `references/` file, or for a `work` route in the pstack playbook its route table names; a skill whose body the main session doesn't need (`polish`, `review`, `compat-check`, `unslop`) is run by an `Agent` told to call it; a procedure with no judgment in it goes in a script under the skill's `scripts/`, with a test for every decision it makes, and its output says what to do next. `scripts/read-budget.json` lists what each route's main session loads and its limit; adding text to a route means cutting something else or moving it out. Lower the limit when a route shrinks.
- **Output language.** The full rule is `plugins/base/references/output-language.md`; a gbase skill's `## 출력 언어` block is a one-line summary that links it (check.py caps the block). Every skill/command carries a `## 출력 언어` block: user-facing text in Korean; PR titles and bodies in Korean by default (template headings stay English; a repo that clearly writes PRs in another language, or a user request, wins); code, paths, commands, status labels, and commit/branch names stay as the target repo's convention. gapp app artifacts (UI copy, store metadata, landing/privacy pages) follow the app language in `docs/HARNESS.md`. Keep the block when editing a skill.

## Writing skills

Follow Anthropic's skill-authoring guidance (platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices, code.claude.com/docs/en/skills). In this repo that means:

- `description`: third person, what it does + when to use it, key use case first; it's the only part always in context (listing truncates at 1,536 chars). Implementation detail belongs in the body.
- Body: only what Claude wouldn't already know — contracts with other skills, safety rules, and gotchas learned from real failures, each with a short reason. No step-by-step coaching of things the model does unprompted, no repeated rules, no long example sessions. Invoked skill bodies stay in context for the rest of the session, so every line is a recurring cost.
- Emphasis (bold, "반드시", NEVER) only on the one or two rules that actually get skipped.
