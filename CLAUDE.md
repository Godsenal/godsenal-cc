# CLAUDE.md

A Claude Code plugin marketplace (`godsenal`) with three plugins — `gbase` (dev workflow: review, polish, PR, monitor), `gapp` (app-building harness: idea → App Store), and `gshorts` (Korean content: faceless short-form videos, Instagram card news). No build step, no dependencies; everything is markdown skills. What each skill does lives in its own `SKILL.md` and in `README.md` — don't duplicate it here.

## Layout

```
.claude-plugin/marketplace.json     registry — one entry per plugin, with version
plugins/base/  → gbase              .claude-plugin/plugin.json, skills/<name>/SKILL.md (+ references/, scripts/), commands/*.md (legacy), evals/ (claude plugin eval cases),
                                    references/ (rules several skills share), .claude-plugin/factory.json (orchestrator slots),
                                    agents/*.md (subagent types, registered as gbase:<name>), hooks/ (SessionStart routing rule)
plugins/app/   → gapp               .claude-plugin/plugin.json, skills/<name>/SKILL.md (+ references/)
plugins/shorts/ → gshorts           .claude-plugin/plugin.json, skills/<name>/SKILL.md (+ references/)
scripts/check.py                    repo checks CI runs (.github/workflows/check.yml); tests for its contract check in scripts/test_check.py
scripts/gbase-run                   headless runner for factory.json slots (claude -p → result.json); tests in scripts/test_gbase_run.py
scripts/read-budget.py              characters a PR run loads into its main session, per route; limits in scripts/read-budget.json (check.py enforces); tests in scripts/test_read_budget.py
scripts/test_ship_prep.py, test_pr_status.py, test_added_comments.py   tests for the scripts the skills run: skills/branch-pr/scripts/ship-prep, skills/monitor/scripts/pr-status, skills/polish/scripts/added-comments
scripts/pstack-sync.py              follows pstack (cursor/plugins): --check / --apply / --verify; lock, upstream snapshots, pending diffs in scripts/pstack/; tests in scripts/test_pstack_sync.py
```

Plugin names carry a `g` prefix (`gbase`); directories don't (`plugins/base/`).

## Conventions

- **New work goes in `skills/<name>/SKILL.md`.** `commands/` holds only the legacy `find-skills` command.
- **Every change bumps the version** in both `plugins/<p>/.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json` (patch for fixes/wording, minor for new or reworked skills) — installed plugins don't update otherwise. Update `README.md` when a skill's behavior or usage changes; update `plugin.json` keywords when skills are added or removed.
- **Read budget.** `work`, `go`, `branch-pr`, and `monitor` bodies hold only the steps every run takes and "when X, read Y". A branch only some runs take (a route's steps, a risk tier, a flag, headless, conflicts, replies) goes in that skill's `references/` file, or for a `work` route in the pstack playbook its route table names; a skill whose body the main session doesn't need (`polish`, `review`, `compat-check`, `unslop`) is run by an `Agent` told to call it; a procedure with no judgment in it goes in a script under the skill's `scripts/`, with a test for every decision it makes, and its output says what to do next. `scripts/read-budget.json` lists what each route's main session loads and its limit; adding text to a route means cutting something else or moving it out. Lower the limit when a route shrinks.
- **Output language.** The full rule is `plugins/base/references/output-language.md`; a gbase skill's `## 출력 언어` block is a one-line summary that links it (check.py caps the block). Every skill/command carries a `## 출력 언어` block: user-facing text in Korean; PR titles and bodies in Korean by default (template headings stay English; a repo that clearly writes PRs in another language, or a user request, wins); code, paths, commands, status labels, and commit/branch names stay as the target repo's convention. gapp app artifacts (UI copy, store metadata, landing/privacy pages) follow the app language in `docs/HARNESS.md`. Keep the block when editing a skill.
- **Cross-skill contracts — change both sides together:**
  - `compat-check`'s verdict tokens (`✅ No special deploy ordering needed` / `⚠️ Requires ordered rollout`) are parsed by `branch-pr`.
  - `go` has `gbase:review` run with `pre-PR mode; defer, don't ask; … start at Stage 2` (plus `one skeptic for low/medium` on medium risk, and on low when headless) and calls `gbase:monitor` with `--no-review` / `--draft` (plus `--until-settled` when headless). The tokens of `go`'s branches live in `skills/go/references/{review,verify,high,draft-merge,orchestrated}.md`, not in its body, and its body names each file with the condition that reads it. `go`, `branch-pr`, and `monitor` run `gbase:polish`, `gbase:review`, `gbase:compat-check`, and `gbase:unslop` through an `Agent` whose prompt is `Skill(skill: "gbase:<name>", …)`, so a subagent can't ask: polish reports what it would have asked as `awaiting confirm`, and review gets `defer, don't ask`; `work` hands `go` its route verification as `behavior:` lines so `go` doesn't re-run it, except on `high`, where `high.md` has an agent that didn't write the code run it, names where `statechart` and `create-formal-verification-skill` come in (a `high` diff that changes a lock, retry, or state machine), and holds `--merge` while a `behavior: skip` or `fail` is left (monitor reads the tier from the PR body's risk line); monitor's `--draft` flip and `--merge` wait on the deferred-findings count `go` passes, and `work` ends with `go`, adding `--merge` only when the user or the project's instructions ask; `go` hands `branch-pr` its risk tier and check results as `Risk:` / `Verification:` / `Deferred:` lines (deferred findings land in the PR body's `## Review focus`), and both classify risk with the same rule (`high` / `medium` / `low`) — change them together.
  - A `behavior: skip` is unverified, not a pass. It is a `(확인)` item in the PR's Review focus (so is a `Verification:` line with `differs:`), a `behavior` `open` line in the evidence file, and an entry of `unverified` in `result.json`; `ship-prep check` fails a draft whose Evidence or evidence file has one without the item. Change `go`'s verify.md, pr-body.md, `orchestrator.md`, `runner.md`, `ship-prep`, `gbase-run`, and their tests together.
  - `branch-pr` and `monitor` act on their scripts' output: `ship-prep` prints `ask:`, `branch plan:`, `compat: run|skip`, `backup:`, and `pr: <url>` lines, and `pr-status` prints `next: conflict|comments|ci|wait|settled|give up|limit`, `merge:`, and the `settle:` line, and `pr-status patch` prints `patch: same|changed` with `next: nothing to re-verify|one verifier` (conflicts.md runs it on a `high` PR after a rebase or base merge: only a changed `git patch-id` re-verifies, with one verifier). A line a skill or reference names must be one the script prints, and the contract tokens of the split-out branches live in `skills/monitor/references/{settle,merge,comments,conflicts}.md` and `skills/branch-pr/references/{pr-body,local-mode,preview}.md`, not in the bodies — change script, skill, reference, and test together.
  - Preview before the PR (`skills/branch-pr/references/preview.md`): the environment file's `## Shipping` line `before the PR: preview` (or `--preview`, or the user asking to see it first) makes `branch-pr` commit and draft locally, write a preview, and ask before anything is pushed. `ship-prep start` prints `preview: on|prepared|changed`, `ship-prep preview <draft>` prints `ship: local …`, `PR 본문 초안:`, `preview: <file>` (the file a person reads, under `$GBASE_HOME/previews/`, outside every repo), and what the preview needs; `--write` saves the text on stdin there (a session's Write tool may be limited to the working directory) and only then records, in `<git dir>/gbase/preview-<sha>.json`, the commit, a digest of the draft, and the files left out or untracked. `ship-prep start` and `ship-prep open` judge "unchanged since" by one function, and `open` refuses anything else, and an environment file it can't read, unless `--no-preview` (the request asked for the PR or the merge in words) or the PR is already open. `--reviewed` marks a commit `go` reviewed: `go`'s Step 1 `cat`s the file by HEAD's sha and goes to Step 5 only on `"reviewed": true` and a clean tree; `go --preview` reaches `branch-pr` through `draft-merge.md`, and ends without Step 6 when `branch-pr` reports `preview:` instead of `pr:`. Headless, the stop holds: the three lines plus a `결정 필요: … → 열지 않음` line, and `gbase-run` (`preview_file`, `unshipped`) does not resume such a run to push. A run with no setting and no request reads nothing more, and `go`/`branch-pr` bodies name only the line and the file. Change `ship-prep` and its test, `preview.md`, `go`, `draft-merge.md`, `branch-pr`, `environment.md`, `conventions.md`, `explore-environment.md`, `orchestrator.md`, `runner.md`, `gbase-run` and its test, the seven `preview-*` evals, and `CONTRACTS` together.
  - `pause` leaves a `wip:` commit whose body is the resume note and starts with an `Intent:` line — the marker `pickup`, `go`, and `branch-pr` use to recognize it; `go` ships unpushed pause commits on a clean tree and `branch-pr` soft-resets all of them into real commits.
  - `setup` writes the `<!-- gbase:verify -->` block in the target repo's `CLAUDE.md` that `go`'s verification gate reads; `create-verify` generates `.claude/skills/verify-*` that `go` runs for touched features, and `go` also runs pstack's `.claude/skills/verify/`.
  - Orchestrator contract (`plugins/base/references/orchestrator.md`, `headless.md`, `.claude-plugin/factory.json`; the runner's own usage and `result.json` live in `references/runner.md`, which no skill links): no orchestrator is ever named in plugin files — only `AGENT_*` variables, files, and report lines. Headless rules live once in `headless.md`; every skill or command that can `AskUserQuestion` points at it in one line (check.py enforces). `go` passes `branch-pr` `Ship-owner: orchestrator; PR-body-file:` and both print the `ship:` / `PR 본문 초안:` lines; `branch-pr` prints `pr: <url>` after opening a PR and `go` carries it up, which `gbase-run` parses into `pr_url` (a `work`/`ship` session that ends with its change but without that line, or `ship:`, is resumed once); `monitor --until-settled` ends with a `settle:` line and rebases only when the invocation explicitly asks to rebase; `go` and `reproduce` write the evidence file format, with an optional `input` field whose `differs:` part `branch-pr` turns into a Review focus item; `gbase-run` parses gshorts' `교훈:` lines into `lessons` and a `next:` work-run command; each `factory.json` slot names a skill that exists in this marketplace (`content` names gshorts' `content-common`), or is the bare `<task>` slot. A shipping step the caller put out of scope gets `ship: skip — <reason>` (headless.md), never a `결정 필요:` line.

  - pstack (`scripts/pstack/lock.json`, `plugins/base/references/pstack-sync.md`): a `follow` item (the followed skills, `agents/poteto-agent.md`, `agents/comment-sicko.md`, `docs/guide/`, `references/pstack-LICENSE`) is generated by `scripts/pstack-sync.py --apply` and never edited by hand — check.py runs the script's `--verify`, which compares it to the lock; to change one, change `references/pstack-adapter.md`, the transform in the script, or its mode. Followed skills keep `disable-model-invocation: true` and are reached by `Read`ing `skills/<name>/SKILL.md`; each links the adapter, which names the gbase skill for every pstack name gbase replaces (`gbase:go` for shipping, `gbase:create-verify`, `gbase:polish`). The daily routine parses `--check`'s fields (`changed`, `skills_changed`, `custom_changed`, `new_upstream`, `removed_upstream`); `custom_changed` also names a followed item that carries `used_by`. A `merge` item's upstream change lands in `scripts/pstack/pending/` and check.py fails until it is merged and the file deleted.
  - `references/conventions.md` is the one place for the order request > repo setting > `gbase.conventions` file > repo history > gbase default (branch, commit, PR title/body, ticket, labels, merge); `branch-pr` and `monitor` link to it instead of restating it, and `gbase-run` reads its `gbase.branchPrefix` key.
  - The environment file (`references/environment.md`): the file `git config gbase.conventions` points at is the user's, lives outside the repo, and holds that environment's conventions, how a ticket is read, and which writes back are `on` / `ask` / `off`. ## Writing skills

Follow Anthropic's skill-authoring guidance (platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices, code.claude.com/docs/en/skills). In this repo that means:

- `description`: third person, what it does + when to use it, key use case first; it's the only part always in context (listing truncates at 1,536 chars). Implementation detail belongs in the body.
- Body: only what Claude wouldn't already know — contracts with other skills, safety rules, and gotchas learned from real failures, each with a short reason. No step-by-step coaching of things the model does unprompted, no repeated rules, no long example sessions. Invoked skill bodies stay in context for the rest of the session, so every line is a recurring cost.
- Emphasis (bold, "반드시", NEVER) only on the one or two rules that actually get skipped.
- Exact commands only for fragile operations (git safety, deploy triggers); prose for judgment calls.
- Keep `SKILL.md` under 500 lines; move bulky reference material to a file linked directly from `SKILL.md` (one level deep).
- Name MCP tools fully qualified (`mcp__<server>__<tool>`).
- Side-effecting skills (push, deploy, submit) keep their own confirmation gate or `disable-model-invocation: true`.

## Verify

- tests: `python3 -m unittest discover -s scripts` — the runner against a fake `claude`, `ship-prep` against throwaway git repos and a fake `gh`, `pr-status` on hand-built API responses (CI runs it too).
- check: `python3 scripts/check.py --base main` — JSON validity, version sync and bump, frontmatter, line/description limits, `## 출력 언어` blocks, the read budget per route, and the cross-skill contract tokens above. CI runs it on every PR (`.github/workflows/check.yml`); when you add a contract, add it to `CONTRACTS` in the script as a `Contract` with a name, the reason its files change together, and its tokens; a failure prints that reason.
- trigger test (manual, not run by `go`): `/plugin marketplace add ./`, `/plugin install gbase@godsenal`, then `/reload-plugins` and give Claude a task that should trigger the skill — confirm it loads the skill rather than improvising.
