# gbase evals

Checks that `gbase:work` loads `gbase:design-taste` when it should and skips it when it shouldn't, that it ships through `gbase:go`, that a small fix stays light, that a headless run reports the slices it left, that a route reads its pstack playbook, that `gbase:go`'s polish step audits the comments a change added, that a ticket is read and written back only the way the user's environment file says, that the pstack verification leaves run only where their condition holds, that a repo whose owner asked for a preview before the PR gets one instead of a push, that a PR whose owner posts their own replies to reviewers gets drafts and no post,, that the reviewers and labels an environment file names reach `gh pr create` while a file without them reads nothing more, that `bug-fix`, `reproduce`, `plan`, `compat-check`, and `review` run on their own as their bodies say and print their report lines, and that `go` keeps its review and its checks when the request asks to skip them.

| `logic-only-skips-design-taste` | a logic-only edit inside a UI file does not load it |

`triggers.json` is not a case: `scripts/check.py` runs it on every PR with no model (`scripts/triggers.py`, TF-IDF over every invocable skill's name and description). Each skill lists prompts that should pick it first from the listing, split into `train` (tune a description against these: `python3 scripts/triggers.py`) and held-out `test` (the only ones judged: `--test`), and prompts that should not; write a test prompt before changing the description it judges, as skill-creator's `run_loop.py` holds out a test split; check.py prints `triggers: rank1 N/M (P%)` and fails when a skill's held-out test prompts fall below its `min_rank1` floor, a negative prompt picks it beyond `max_negative_hits`, or two descriptions are more alike than `max_similarity` (pairs in `similar_pairs` excepted). A floor records today's value for a skill that doesn't pass yet; fix the description to raise it, never reword the prompt. `python3 scripts/triggers.py` shows every train miss with its top three, `--test` the judged ones, `--pairs` the most similar descriptions.

Run from `plugins/base` (8 cases at 3 runs each took about 13 minutes and $6; there are 42 now):

```bash
claude plugin eval . --ablation none --scaffold --trust-plugin --allow-tools Edit Write --no-publish --threshold 0.67
```

- Keep the results out of the repo: add `--output-dir <dir outside the plugin> --json <file>.json` (the default writes `evals/results/<timestamp>/`, which is not committed).
- Run one case only: add `--case <name>` (a name glob, e.g. `--case chore-ships-through-go`).
- Change the number of runs per case: add `--runs <n>` (default: the case's `runs` if set, else 3).
