# Runner

`scripts/gbase-run` in this repo is one way to be the caller: it runs a single slot with `claude -p` and leaves a result file for a poller. It reads the manifest and the [orchestrator contract](orchestrator.md) and adds no skill behavior.

```
gbase-run --repo <path> --slot <slot> [--task "..." | --task-file <path>] [--worktree <name>]
          [--base <ref>] [--model opus|sonnet] [--ship-owner orchestrator|agent] [--answers <file>] [--exclusive]
          [--account <name>] [--notify-cmd "<cmd>"] [--max-turns <n>]
gbase-run --dir <folder> --slot task|content [--task "..." | --task-file <path>] [--model opus|sonnet] [--answers <file>]
          [--account <name>] [--notify-cmd "<cmd>"]
gbase-run start <the same arguments>
gbase-run status <run-id>
gbase-run stop <run-id> [--reason "..."]
gbase-run list
gbase-run cite <run-id>
gbase-run land <run-id> [--onto <branch>]
gbase-run gc [--older-than 3d] [--dry-run]
gbase-run doctor
```

- **When the runner is updated, a feature that needs setup is switched on in the same deploy, then checked with `gbase-run doctor`.** 1.41.0's account switching and gc shipped while the Mac mini had no accounts file and no gc schedule, and nothing said so until a retro (2026-11-04). `doctor` prints one JSON object: `accounts_source` (`GBASE_ACCOUNTS`, the accounts file, or `null`), each account with its config dir, aliases, and preflight result, whether `GBASE_NOTIFY_CMD` is set, the last `gc` and `gc --dry-run` (`gc_last`, `gc_dry_run_last`: `{at, <action>: count}` from `$GBASE_HOME/gc-last.json` and `gc-dry-run.json`), the worktrees' count and size, and `problems`; it exits 1 when there is one.

- **Usage-limit and login retries are the runner's job.** List the accounts in `GBASE_ACCOUNTS="default:~/.claude,c5:~/.claude-5"` or in `$GBASE_HOME/accounts` (one `name:config-dir` per line); don't write a `CLAUDE_CONFIG_DIR` retry block into a run script. Before a worktree is made, the runner checks the first account with `claude -p ok --max-turns 1` (cached `GBASE_PREFLIGHT_TTL` seconds, default 300, in `$GBASE_HOME/accounts.json`) and skips one that answers `Not logged in` or a usage limit. A session that still ends on either before any tool call is run again, same prompt, on the next account. An account that auth-failed on a run of the same `--task` in the last day goes last, and an `--answers` run starts on the answered run's account. A config dir of `~/.claude` runs with `CLAUDE_CONFIG_DIR` unset, as plain `claude` does. Names on the same config dir (`c5:~/.claude-5` and `vixen:~/.claude-5`) are one login: the first name is the account, and the later ones are aliases for it. `--account <name or alias>` puts that account first, ahead of the answered run's and of one that auth-failed on the task; `account` in `result.json` and `cite` then show the first name. A name the list doesn't have fails the run before it starts; with no list at all, `--account` is ignored with a warning and the run goes on as `default`. With no accounts listed, the run uses the runner's own environment as `default`, unchecked, a login or limit failure still fills `failure`, and the run leaves a warning in `warnings` and, when nothing else claims it, `next`.

- **A session stops at `--max-turns`** (default `$GBASE_MAX_TURNS`, else 300; `0` = no cap). The cap is a guard against a run that never converges, not a budget: the longest of the first 168 work runs took 264 turns. A session that reaches it is not resumed to ship. It gets one short wrap-up session that reports what is done, what is half-done, `남은 작업:` lines for the rest, and a `결정 필요:` line; `result.json` then carries `turn_limit` and `followups`, and the change stays in the worktree.
- A run in the background is one line: `gbase-run start …` (the run's arguments). It starts the runner in its own session and returns once `result.json` exists, printing the run id and then the `result.json` path; the runner's own output goes to `runner.log` in the run directory, so read the `next:` command from `next` in `result.json`; `status`/`stop` work on it as on any run. An argument the runner rejects fails `start` itself, with the runner's error. Don't write `nohup claude -p …` or `--dangerously-skip-permissions` on the command line: the runner already passes `--permission-mode`, and a long command with that flag is the one a permission classifier blocks (the morning content runs of 2026-10-29 and 10-30 never started).
- `--dir <folder>` runs the `task` or `content` slot in a plain folder (`~/.gbase/tasks/<name>`), git or not, instead of `--repo`: no worktree, base, or concurrent-run check, so it can't take `--worktree`, `--base`, or `--exclusive`. `repo` in `result.json` is `null` and `dir` is the folder.
- The prompt is the slot's `invoke`, with `--task` replacing a `<placeholder>` or appended. A slot whose `invoke` is `null` gets a prompt built from its `notes`. `--task-file` reads the task from a file — use it for a long task instead of `--task "$(…)"`, where a heredoc quoting slip pastes shell lines into the prompt.
- The child runs with `AGENT_HEADLESS=1`, `AGENT_SHIP_OWNER` from `--ship-owner` (default `orchestrator`, so nothing leaves the machine), `AGENT_PR_BODY_FILE` and `AGENT_EVIDENCE_FILE` in the run directory, `GITHUB_TOKEN` removed, gbase loaded with `--plugin-dir` from the same checkout — plus the plugin a slot's `invoke` names (`content` → `plugins/shorts`) and any in `GBASE_PLUGIN_DIRS`, so other plugins' skills stay out of dev runs — and `--disallowedTools ScheduleWakeup,CronCreate` ([headless.md](headless.md#end-when-the-work-ends)). A slot whose `invoke` names a `/<plugin>:<skill>` no loaded dir has fails before claude starts. `AGENT_ASK_CMD` is `$GBASE_ASK_CMD` when set; otherwise `gbase-run question <run-id>`, which records each question in `questions.jsonl` and gives no answer, so the skill applies its recommendation and writes a `결정 필요:` line.
- The model is `--model`, else the answered run's when `--answers` names a run of the same slot, else the slot's `model`, else claude's default; a `models` slot ignores it and runs its own list. Each run is a new session, so switching models between runs costs no prompt cache, and the in-run resume keeps its session's model. The cache is per model: resume a session by hand with `--model` set to its `sessions.<…>.model` from `result.json`, since without it claude picks the account default and writes the whole conversation to the cache again.
- `--repo` may be any checkout of the repo; `repo` in `result.json` is its main worktree, while claude runs in the path given (or `--worktree`). Runs are matched to a repo by origin's URL (host and path), so two clones of one repo count as one.
- Another run still `running` on the same repo → a warning on stderr and its run ids in `concurrent`. `--exclusive` runs take turns on a per-repo lock in `$GBASE_HOME/locks/` (the kernel's, so two that start in the same second still go one at a time, and a runner that dies frees it), and the holder then waits for the runs that were going on the repo when it got the lock — before creating a `--worktree` branch, so it starts from the newer base. One still in line has `"waiting": true` in `result.json` and isn't waited on. Use it for runs that edit the same files.
- `--worktree <name>` runs in the worktree that already has branch `gbase/<name>`, else `$GBASE_HOME/worktrees/<repo>-<main checkout path hash>-<name>`, created on first use with no upstream from `--base` (default: origin's default branch after `git fetch origin`; with no `origin`, the branch the main checkout has checked out) and reused after — never from whatever the main checkout has checked out, whose unpushed commits would ride into the PR. A reused branch isn't rebased; `base` in `result.json` shows how far it is from the base. A branch whose tip is the head of a merged or closed PR (`gh pr list --head`) isn't reused: it's renamed `gbase/<name>-pr<N>`, its worktree moved to `<path>-pr<N>`, and the name starts over from the base.
- A run whose report has `교훈:` lines (any slot but `work`) writes them into `lessons.md` in its run directory and prints, before the last line, `next: gbase-run --repo <this checkout> --slot work --task-file <run_dir>/lessons.md --worktree lessons --exclusive` — the `work` run that ships them; `next` in `result.json` holds the same command. Every lessons run shares the `lessons` branch until its PR ends, so a second content run's lessons join the open PR instead of opening another one on the same skill files and version line.
- **A local-only run is finished only when `landed.contains_head` is `true`.** In a repo with no `origin`, the base is the branch the main checkout has checked out (the one the repo's other jobs use), and an orchestrator-owned run records `landed: {ref, contains_head}`. When the run's commits aren't on that branch, `next` says so: ``커밋 <sha>는 gbase/<name>에만 있음. <ref>에 넣으려면 `gbase-run land <run-id>` ``. `land` fast-forwards the branch to the run's head, or cherry-picks the run's commits onto it in a scratch worktree; on a conflict, merge commits, or uncommitted changes where the branch is checked out, it stops and changes nothing. A run reported "done" without landing left a fix off the daily branch for half a day (2026-11-02).
- `gc` removes worktrees under `$GBASE_HOME/worktrees` whose newest run is `done`, `failed`, or `dead` (its runner crashed), that finished more than `--older-than` ago (default `3d`) and have no uncommitted changes, and whose commits are all in the run's base (ancestors or patch-equivalent), whose PR (under the branch's name before a `-pr<N>` rename) is merged or closed, or that have no commits. Branches stay. `--dry-run` prints the plan only. Run it daily from the same scheduler that starts the bot's runs (on the Mac mini, the bot's schedule; not a cron of its own the bot doesn't know about): `gbase-run gc --older-than 3d`. Each `gc` records its time and counts for `doctor`. The first real `gc` on a machine runs only after a person has read its `--dry-run` list: a backlog can be tens of GB of worktrees. A worktree a run created and never worked in (every session failed on login or a usage limit) is removed when that run ends.
- A `work` or `ship` run whose session ends with work left in its worktree (uncommitted changes, or commits no remote has) and no `pr:` line (`--ship-owner agent`) or `ship:` line (`orchestrator`) is resumed once with `claude --resume` and a prompt to finish `gbase:go` from where it stopped; that session gets `"resumed": true`, and its `cost_usd` covers both.
- The last stdout line is the absolute path of `result.json`. Exit 0 when every session exited 0. SIGTERM, SIGINT, or SIGHUP (`gbase-run stop <run-id>` sends SIGTERM and waits) ends each claude session's process group — subagents and shells included, SIGKILL after 10 s — and still writes the result (`failed`, with `stopped_by`, and `stop_reason` from `--reason`). A claude session that exits on a signal nobody sent through `stop` gets `stopped_by: "child SIGTERM"` (or `SIGKILL`, `SIGINT`).
- A slot whose `invoke` has a `<placeholder>` (`work`, `reproduce`) needs `--task`.
- **One completion signal: `result.json` plus the notify command.** `--notify-cmd "<cmd>"` (default `$GBASE_NOTIFY_CMD`) runs once after the final `result.json` is written, success or failure, as `sh -c '<cmd> "$@"' notify <run-id> <status> <exit-code> <result.json path>`. Make it one command, a script with its arguments: after a `;` or `#` the run's arguments go to the wrong command or nowhere. The command reads its URL or key from its own file or environment; the runner never writes the command line into `result.json`, the run directory, or its output, and the claude session doesn't inherit `GBASE_NOTIFY_CMD`. `notify` in `result.json` is `ok` or `failed` (non-zero exit or 60 s timeout); a failed notify doesn't change `status` or the exit code. A bot keeps a one-shot check on `result.json` until its notify receiver has proven itself.
- The session gets `GBASE_RUN_ID`, for names it leaves outside the run directory (ego task spaces: [ego-profile](../skills/ego-profile/SKILL.md)).
- A bot that runs Claude itself instead of through the runner copies the recipes in [harness.md](harness.md).

Run directory `$GBASE_HOME/runs/<run-id>/` (`GBASE_HOME` defaults to `~/.gbase`): `prompt.txt`, `log.jsonl` (the `stream-json` events; `log-<model>.jsonl` per session for a `models` slot), `final.md` (the last result message that carries a report line, else the last one; `final-<model>.md`), `evidence.jsonl`, `pr-body.md` when `go` drafted one, `questions.jsonl`, `answers.json`, `review.md` for a `models` slot, `runner.log` for a `start` run, and `result.json`:

| Field | Value |
|---|---|
| `run_id`, `slot`, `task`, `repo`, `dir`, `cwd`, `worktree`, `model`, `ship_owner` | the inputs (`repo` is `null` for a `--dir` run, `dir` `null` otherwise); `cwd` is where claude ran |
| `status` | `running` until the runner finishes, then `done` or `failed`; `status` reports `dead` for a `running` file whose runner process is gone, or whose pid now belongs to a process that started after the run |
| `pid`, `started_at`, `finished_at`, `run_dir`, `prompt_path`, `log_path` | bookkeeping |
| `exit_code` | the highest exit code of the claude sessions |
| `branch`, `head_sha` | of `cwd` after the run |
| `base` | `{ref, ahead, behind}`: commits of `cwd`'s `HEAD` after the run not in `ref` and the other way round, or `null` with no base (a `--dir` run, or a detached `HEAD` in a repo without `origin`); before pushing, check `ahead` against the commit count of the `ship:` line |
| `landed` | orchestrator-owned runs in a repo without `origin`: `{ref, contains_head}`, whether `ref` (the base branch) contains the run's head; `land` sets it to `{ref, contains_head: true, sha, method}`. `null` otherwise |
| `account`, `failures`, `failure` | the account name the session ran on (`default` with none listed; never a path); every login or usage-limit failure as `{kind: "auth" \| "usage_limit", account, detail, stage: "preflight" \| "run"}`; and the one that ended the run when no session got past them, else `null` |
| `provenance`, `skills` | the one-line `gbase-run cite` output, and the skills the run's prompt and its top-level `Skill` calls named, in order |
| `stop_reason`, `worktree_removed` | the `stop --reason` text; `true` when the run's own never-used worktree was removed. Absent otherwise |
| `decisions` | every `결정 필요:` line, in order, as `{text, question, applied, recommend, options, human, incomplete}` ([format](headless.md#결정-필요-lines)): `text` is the raw line (before v1.28.0 the list held only these strings); a part the line lacks is `null`, except `options`, which is `[]` when the line lists none. `incomplete` is `true` when there's no `추천` and the question only points at the report (`위 2건을 확인해 주세요`): pass `final.md` along with it |
| `ship`, `settle` | the last `ship:` / `settle:` line of any result message in the session (a session can end more than one turn), or `null` |
| `pr_url` | the URL from the last `pr:` line (`--ship-owner agent`); without one, for `settle` and for an agent-owned `work`/`ship` run, the current branch's open PR from `gh pr view` (a session that opened a PR can end with only its `settle:` line); else `null` |
| `followups` | the `남은 작업:` lines in order, without the prefix: slices a `work` run left for later runs, or what a run stopped by the turn cap still had to do |
| `turn_limit` | the turn cap, when a session reached it; else `null`. The run then got one wrap-up session of at most 30 turns and didn't ship |
| `lessons`, `next` | the `교훈:` lines in order, and the `next:` command for them; without lessons, the `land` sentence of an unlanded local-only run; without either, the first of `warnings`; else `null` |
| `warnings` | setup problems the run ran around (no accounts list); `[]` otherwise |
| `notify` | `ok` or `failed` when a notify command ran; absent otherwise |
| `concurrent` | run ids that were `running` on the same repo when this one started; absent when none |
| `mockup` | `{html, url, screenshots}` from the `mockup` lines (`url` is `null` for `none`), or `null` |
| `pr_body_file` | the path from `PR 본문 초안:`, else `pr-body.md` if it exists, else `null` |
| `evidence` | the parsed evidence lines |
| `questions` | each `{question, recommend, options}` sent to the default `AGENT_ASK_CMD` |
| `sessions` | per model: `session_id`, `model`, `exit_code`, `cost_usd`, `log_path`, `final_path` |
| `answers_from` | the run the answers file named; `model` is inherited from it too when the slot is the same |
| `findings`, `report_file` | `models` slots only: `{severity, location, finding, action, found_by}` and the merged table |

A follow-up run answers a run's decisions with `--answers <file>`:

```json
{
  "run_id": "<run whose decisions these answer>",
  "answers": [
    { "decision": "<a 결정 필요: line or its question, or a question from questions.jsonl>", "answer": "<option label or instruction>" }
  ]
}
```

`run_id` is optional; when given, `--repo`, `--slot`, `--task`, and `--ship-owner` default to that run's, and the run continues in that run's `cwd` (its worktree, where its edits are). The answers go into the prompt as decisions already made, and a question asked again gets its answer from `AGENT_ASK_CMD` — the exact text first, then ignoring case, a leading `결정 필요:`, and how whitespace and punctuation are spaced (`Use the cache?` matches `use the cache`; `v1.2.0` doesn't match `v12.0`). When answers that differ match only after normalizing, none is given. A `decision` that starts with `결정 필요:` is a pasted report line: only its question counts, so the `→ …` tail, the `(추천: …; 다른 선택지: …)` group, and `· AGENT_ASK_CMD 에 넘김` are dropped.

Environment of the runner itself: `GBASE_CLAUDE` (default `~/.claude/local/claude`, else `claude` on `PATH`), `GBASE_HOME`, `GBASE_PLUGIN_DIR` (default `plugins/base` of the checkout), `GBASE_PERMISSION_MODE` (default `bypassPermissions`; the child has no person to approve tools), `GBASE_ASK_CMD`, `GBASE_ACCOUNTS`, `GBASE_PREFLIGHT_TTL`, `GBASE_NOTIFY_CMD`.
