# /gapp:next — 현재 위치 파악 → 다음 단계 실행

세션이 바뀌어도 하네스가 이어지게 하는 재개 버튼. **기본 동작은 보고가 아니라 진행이다** — 현재
위치를 3줄로 요약해 보여주고, 곧바로 다음 단계 스킬을 이어서 실행한다.

## 출력 언어

사용자와의 대화 — 진행 보고, 요약, 체크리스트/판정 표, `AskUserQuestion`의 질문·헤더·옵션·설명 — 은 **한국어**로 쓴다. 하위 에이전트를 띄울 때도 결과가 사용자에게 그대로 노출되는 텍스트는 한국어로 돌려달라고 프롬프트에 적는다.

영어 그대로 두는 것: 코드·식별자·파일 경로·명령어·환경변수·워크플로 YAML·스킬/툴 이름, 고정 라벨과 상태 키워드(`PASS`/`FAIL`/`SKIP`, `✅`/`⚠️`), 그리고 커밋 메시지·브랜치 이름·PR 제목/본문 — 이건 대상 레포의 기존 관례를 따른다.

**앱 산출물은 이 규칙이 아니라 `kickoff`에서 정한 앱 언어(`docs/HARNESS.md`)를 따른다.** 앱 UI 문구, 랜딩 카피, 개인정보/지원 페이지, 스토어 메타데이터·스크린샷 문구는 전부 앱 언어로 — 영어 앱에 한국어 스토어 메타데이터를 넣지 않는다.

사용자가 다른 언어로 요청하면 그 언어를 따른다.

## 절차

1. **`docs/HARNESS.md`를 찾는다.** 현재 디렉토리 → 상위 순. 없으면:
   - 레포가 비었거나 새 프로젝트 기색 → `/gapp:kickoff`를 바로 이어서 실행.
   - 기존 앱 레포 → 레포를 스캔(아래 증거표)해 HARNESS.md를 소급 생성하고 유저에게 확인받은 뒤 진행.

2. **문서 vs 실제 레포 드리프트 검사** (어긋난 것만 보정):
   | 단계 | 실제 완료의 증거 |
   |---|---|
   | scaffold | `package.json`에 expo + `app.json` + CLAUDE.md 존재 |
   | design | `theme/tokens.ts`(또는 동급) + `DESIGN.md` 존재 |
   | backend | `supabase/` 디렉토리 + migrations 존재 |
   | cicd | `.github/workflows/`에 ci/eas-update/eas-build 존재 |
   | analytics | `lib/analytics/` (또는 동급) + `next.config`에 `/ingest` rewrite + `.env.example`에 POSTHOG 키 |
   | landing | 웹 디렉토리(예: `web/`) + 개인정보처리방침 페이지/URL 존재 |
   | store-assets | 스크린샷 디렉토리 + `docs/APPSTORE-METADATA.md` 존재 |
   | store-submit | HARNESS.md 로그에 제출 기록 (레포 밖 상태라 문서가 진실) |

   증거는 있는데 체크가 안 돼 있으면 체크하고 로그에 "next가 보정" 한 줄. 반대(체크됐는데 증거
   없음)면 유저에게 어느 쪽이 맞는지 확인.

3. **요약 3줄 출력 후 바로 진행:**
   ```
   📍 <앱이름> — <단계 N>까지 완료 / 다음: <단계 N+1>
   결정 요약: <핵심 2줄>
   → /gapp:<skill> 이어서 실행한다. (멈추려면 지금 말해줘)
   ```
   그리고 해당 스킬을 **실행한다**. 유저 입력이 필요한 지점(취향/시크릿/비용/배포 트리거)은 각
   스킬이 알아서 멈춘다 — next가 미리 겁먹고 멈추지 않는다.

4. **전 단계가 끝난 프로젝트면** 개발 루프 모드: 미커밋 변경·열린 PR·최근 HARNESS 로그를 훑어
   진행 중인 일을 찾아 이어가고, 배포할 게 쌓였으면 `/gapp:deploy`를 제안·실행한다. 릴리스가
   임박했으면 `/gapp:preflight`.
